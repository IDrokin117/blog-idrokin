# Redesign of the personal site

## Problem Statement

The site is built on a third-party Zola theme (`pico`, a git submodule) with local overrides on top. It looks generic, carries features that aren't needed (search, comments), mixes Russian and English, names the blog section "Notes" in config but "Posts" in the menu, shows a Projects section although there are no public Projects, and keeps the Resume as a hand-maintained HTML page plus a separately maintained PDF. Authors of Posts cannot group them into a Series. The owner wants a pleasant, restrained design that does not look like generic AI-generated output, aimed at recruiters and fellow engineers.

## Solution

Rebuild the site with its own templates and styles, without a third-party theme. The look is typographic minimalism: single column, serif body text, warm neutral background, one accent color, light and dark themes following the reader's system setting. The site is in English only. Navigation is Home, Posts, Resume. Posts can belong to a Series. The Resume is written once in markdown and published both as an HTML page and as a PDF produced automatically on every deploy. Projects stay in the repository but are hidden until real ones exist. Quizzes are not built now, but a page must be able to load its own small script later.

## User Stories

## Implementation Decisions

- Site language is English; single language, no i18n.
- Remove the `pico` theme dependency entirely; the site has its own base layout, header, footer, page templates and one stylesheet (Sass compiled by Zola, a few hundred lines).
- Visual direction: typographic minimalism with editorial warmth. One column; one self-hosted variable serif (Source Serif 4, regular and italic, woff2) for text and headings; system sans-serif for small UI details (dates, Series label, navigation); warm neutral background; one accent color; no gradients, glass effects, icon grids or hero images. Exact palette is decided during implementation and reviewed by the owner.
- Light and dark themes via the system preference only; no toggle. Code highlighting uses class-based output with two small color sets aligned with the palette.
- Menu: Home, Posts, Resume. Series and Tags are secondary pages with no menu entry; Series are listed at the top of the Posts page, tags are links under a Post.
- Rename the blog section consistently to "Posts" (config, section title, headings).
- Home page: name, one or two lines about the author, small avatar next to the name, links to Resume, GitHub, LinkedIn, Email; then the three latest Posts; then a Series block only if Series exist. The "about" text is drafted from the Resume and approved by the owner.
- Series: a Zola taxonomy named `series`. A Post declares its Series via the taxonomy and its position via a Part number in its extra front matter. Series title and description live in a content page per Series. A Post may be in at most one Series; the template uses the first value and a build check warns on more than one. Part ordering is by Part number. Draft Parts are excluded from every list and navigation.
- Post page with a Series: label above the title ("Series name · Part N of M", linking to the Series page); at the end, previous/next within the Series and a collapsed list of all published Parts.
- Resume: single markdown content file; contacts (email, GitHub, LinkedIn, location) in front matter; body with Summary, Experience, Skills, Education headings. Template only lays out and styles; print stylesheet makes browser printing produce a clean document. Existing resume content is moved, not rewritten.
- Resume PDF: produced in the deploy pipeline by rendering the built Resume page with a print-capable HTML-to-PDF tool, written into the site output at a stable URL, linked from the Resume page as "Download PDF". The current GitHub Pages deploy action is replaced by explicit steps: checkout, install Zola, build, link check, generate PDF, publish to the same `gh-pages` branch. A single local command reproduces the build and the PDF.
- Projects: section stays in the repository but is not rendered, absent from the menu, and its sample page is a draft. The Project page format is defined as: title, one-line summary, stack list, repository link, status (active/archived), optional demo link; the list is a plain list with summary and stack, no cards or images. Revealing Projects is a config change.
- Remove search (index generation and widget) and comments (giscus configuration and widget). Keep tags and the RSS feed (enable feed generation).
- Keep domain, CNAME, deploy branch and all existing Post URLs.
- Quizzes are not built. The only constraint: a page may declare its own script to load, with no site-wide script bundle.
- Fonts are self-hosted; no third-party requests at runtime.
- Line endings are normalized to LF (already done) and development happens on the `redesign` branch; `main` is untouched until the redesign is ready.

## Testing Decisions

- A good test checks only what a reader sees in the built site (pages that exist or don't, links, order, text), never template or style internals.
- There is a single seam: the output of the Zola build. A test builds the site from a dedicated fixture content set (Posts, a two-Part and a draft-containing Series, a Post outside any Series, a Resume, a hidden Project) and asserts on the resulting HTML and files.
- Covered: menu items are exactly Home, Posts, Resume; no Projects page or link; Series label, Part numbering, prev/next and Parts list; ordering by Part number rather than date; drafts excluded; home page shows three latest Posts and a Series block only when Series exist; Resume page renders from markdown and links to a generated PDF that exists; RSS feed exists; existing Post URL is unchanged; no search or giscus assets; no third-party font requests.
- The same build also runs Zola's internal link check in the deploy pipeline before publishing.
- Not automated: visual quality, typography, dark mode, print appearance and the PDF's look; these are reviewed manually in a browser (light, dark, phone width).
- Prior art: none; the repository has no tests today.

## Out of Scope

- Quizzes and any interactive content, including their data format.
- Real Projects content and any Projects design beyond the page format.
- Russian or other language versions.
- Search, comments, analytics, theme toggle.
- Writing new Posts or rewriting the Resume content.
- Changing domain, hosting or deploy branch.
